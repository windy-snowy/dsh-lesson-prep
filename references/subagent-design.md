# 子代理设计：默认单代理，按需双代理并行

## 一、为什么默认不用子代理

- 备课包的大部分时间花在**有先后依赖**的步骤上（裁剪 → 原理图 → 合并），子代理无法加速；
- 子代理各自持有上下文，跨代理传大文件容易失真；
- 默认单代理可预期、可调试，也省上下文预算。

所以：**没有明确要求就不召唤子代理**，只在开工前说一句提示，不追问。

## 二、怎么召唤

三种等价方式，任选其一：

1. 命令行加 `--subagent-mode parallel`；
2. 用户说「**用子代理模式**」「并行跑」「两个子代理分工」；
3. 单独生成提示词后手动派发：

```bash
python3 scripts/lesson_prep.py prompts \
  --title "第7章 循环神经网络" --run-dir ./runs/rnn-90 \
  --subagent-mode parallel --slide-mode both --out ./runs/rnn-90
```

会得到三份提示词：

| 文件 | 给谁 |
| --- | --- |
| `子代理A-幻灯与原理图.md` | 幻灯子代理（slide-forge：图片版 + 元素版 + 原课件风格） |
| `子代理B-素材与文案.md` | 素材子代理（代码 / 视频 / 题目 / 方案正文） |
| `主代理-总装与验收.md` | 主代理自己（总装、合并、打包、验收） |

## 三、职责切分（核心：写入目标零重叠）

| | 子代理 A · 幻灯与原理图 | 子代理 B · 素材与文案 |
| --- | --- | --- |
| 技能 | `slide-forge`（图片版 + 元素版） | 无（纯脚本 + 检索 + 写作） |
| 读取 | `deck.json`、`plan.json`、`style.json` | 同左 |
| 写入 | `slides/**`、元素版 PPTX | `demos/**`、`06-视频/**`、`08-数据集图片/**`、`01-课程方案.md`、`03-讨论题.md`、`04-课后习题.md` |
| 耗时特征 | 逐页生图（每页数分钟）+ 元素版逐页重建 | 代码运行（秒级）+ 视频下载（分钟级）+ 写作 |
| 失败降级 | 停在 `deck_spec.json`；元素版失败则逐页交付 | 视频清单照常、代码回退合成数据 |

两个子代理**不会写同一个文件**，因此并行不会互相覆盖，也不需要锁或顺序约定。

## 四、哪些步骤必须留在主代理（串行）

1. `all` 里的确定性步骤：抽页、时间盒与删页、裁剪、风格提取——它们产出两个子代理的输入；
2. `merge`：依赖子代理 A 的 `slides/`；
3. `bundle`：依赖全部产物；
4. `verify_pack`：依赖全部产物，且是质量闸门；
5. 人工确认点（例如原理图总览图的取舍）不并行、不跳过。

## 五、并行只加速"无依赖且耗时"的那部分

```
时间线（parallel 模式）

主代理  ├─ all（确定性步骤，秒级～分钟级）
        ├─ 派发 A ─────────────────────────────┐
        ├─ 派发 B ─────────────────────────┐   │
        │                                  │   │
        │   A：写 spec → 生图 ×3 → qa → 图片版 → 元素版
        │   B：复核 → 代码 → 数据图 → 视频检索下载 → 题目 → 方案
        │                                  │   │
        ├──────────────────────────────────┴───┘
        ├─ merge（串行，依赖 A）
        ├─ bundle（串行）
        └─ verify_pack（串行，质量闸门）
```

加速来源：B 的视频下载与代码运行和 A 的逐页生图完全重叠。
不加速的部分：任何有依赖关系的步骤，以及质量闸门。

## 六、质量不被并行影响的四个保障

1. **输入冻结**：两个子代理只读同一份 `deck.json` / `plan.json` / `style.json`，主代理在派发后不再改这些文件；
2. **产物隔离**：写入目录零重叠（见第三节表格），失败也只影响各自产物；
3. **闸门串行**：`qa`（原理图）、`verify_pack`（整包）与人工确认都由主代理串行把关；
4. **如实汇报**：任一子代理降级，主代理必须把降级原因与影响范围写进最终汇报，不能合并成"已完成"。

## 七、反模式（不要做）

- ❌ 让两个子代理都去改 `02-精简课件.pptx`（会互相覆盖）；
- ❌ 让子代理 A 等子代理 B 的产物（产生假依赖，抵消并行收益）；
- ❌ 主代理在等待期间重复子代理的工作（浪费 token 且可能写出冲突版本）；
- ❌ 因为并行就跳过 `qa` / `verify_pack`；
- ❌ 用户没要求时为了"更快"擅自开启子代理。
